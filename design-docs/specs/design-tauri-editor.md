# Design: standalone Tauri 2 editor example (`examples/tauri-editor`)

**Status.** Accepted for implementation.

**Scope.** A new self-contained subproject at `examples/tauri-editor/`, plus minimal root wiring: the README, the root `tsconfig.json`, the root `vite.config.ts` and `.gitignore`. emaki library sources (`src/`) and the root `package.json`/`package-lock.json` do not change. vactr and chilla are not modified. `chilla/src-tauri` is a read-only reference for Tauri 2 conventions.

## 1. Baseline (HEAD 1d1ac81)

- **Package exports.** `package.json` exports TypeScript source: `.` → `src/index.ts` and `./languages` → `src/language/registry.ts`. The only peers are `@codemirror/state` 6.7.6 and `@codemirror/commands` 6.11.1.
- **Editor API.** `createEditor(host, { doc, language, theme: { tokens } })` returns an `EditorHandle` with:
  - `state`, `setDoc`, `focus` and `destroy`
  - `onUpdate(cb)`, where an `EditorUpdate` carries `docChanged`, `selectionSet` and `state`

  The language is fixed at creation; changing it at runtime is a non-goal of `design-syntax-highlighting.md` section 2.
- **Language registry.** `src/language/registry.ts` provides:
  - `languages: LanguageInfo[]`, which includes `plaintext`
  - `resolveLanguage({ filename })`
  - `loadLanguage(id)`, which is lazy (`import()` per language) and cached
  - a re-export of `defaultTokenColors`
- **CSP compatibility.** `src/` uses no `eval`, `new Function`, workers, blobs, wasm, `innerHTML`, `<style>` injection or `style` attributes. It sets styles through the CSSOM (`el.style.x`), which a CSP without `'unsafe-inline'` allows.
- **Root gates.**
  - The root `tsconfig.json` `include` lists `examples`. Without an exclusion, it would type-check the subproject.
  - The root `vite.config.ts` uses `root: 'examples'` with five explicit rollup inputs, so the build ignores the subproject. Dep pre-bundling, however, crawls every `examples/**/*.html` by default, and the dev watcher would watch `src-tauri/target`.
  - The root `vitest.config.ts` only includes `test/**/*.test.ts`, so it is unaffected.

## 2. Goals and non-goals

**Goals.** These come from the intake acceptance signals:

- Open a native window with an emaki WebGL2 editor that fills it.
- Support New, Open, Save and Save As, plus opening a file passed as a CLI argument.
- Show a title with a dirty marker, and confirm before discarding unsaved changes.
- Detect the language lazily, with a plaintext fallback, a status bar and a language override.
- Pass standalone frontend and Rust gates.
- Add a mocked-IPC Playwright smoke test and record a native build log.
- Keep the root gates green.

**Non-goals.**

- A multi-tab or multi-window editor.
- Find/replace or settings.
- Preserving CRLF line endings: emaki's CodeMirror `Text` normalizes them to `\n`, and Save writes LF.
- Detecting the encoding of non-UTF-8 files, which are rejected.
- Bundled installers: only `--no-bundle` is verified.
- Restricting app commands with an `AppManifest` allow-list.
- Atomic writes.
- Keeping undo history across Open or a language override.

## 4. Consuming emaki

- **Vite aliases.** These map `emaki` → `../../src/index.ts` and `emaki/languages` → `../../src/language/registry.ts`. Use exact-match aliases (regex `^emaki$`, `^emaki/languages$`).
  - `server.fs.allow` includes the repository root, so the dev server can serve `../../src`.
- **TypeScript paths.** `tsconfig.json` `compilerOptions.paths` uses the same two mappings. Its compiler options mirror the root ones: strict, bundler resolution, `ES2022`, DOM, and `types: []`. `include` is `["src", "vite.config.ts"]`.
- **No `file:` dependency.** emaki's sources resolve `@codemirror/*` from the root `node_modules`, so there is exactly one CodeMirror instance. The subproject never imports `@codemirror/*` itself.
- **Prerequisite.** Run the root `npm install` before the subproject install. The README states this.

## 5. Native side (Rust, `src-tauri`)

**Dependencies.**

- `tauri = "2"`, `tauri-build = "2"` and `tauri-plugin-dialog = "2.7.0"`. These match the chilla reference versions from the intake.
- No serde, no tokio and no dev-dependencies: tests use `std::env::temp_dir()` with unique per-process names.
- `crate-type = ["staticlib", "cdylib", "rlib"]`, following the standard Tauri 2 template.
- Build with `~/.cargo/bin/cargo` (rustup stable 1.97).

**Path scope (the security boundary).** `AppState { granted: Mutex<HashSet<PathBuf>> }`. A path enters the set only in three ways:

1. The CLI argument at setup. This is the first argument after the binary name that does not start with `-`, made absolute with `std::path::absolute`.
2. A path returned by `pick_open_path`.
3. A path returned by `pick_save_path`.

The webview cannot read or write any path outside this set.

**Commands.** Every command returns `Result<T, String>`, and the error strings are shown in the status bar.

| command | behavior |
|---|---|
| `initial_path() -> Option<String>` | Returns the granted CLI path, if any. |
| `pick_open_path() -> Option<String>` | Opens a native file dialog with `tauri_plugin_dialog` `blocking_pick_file` inside an `async` command, so it runs off the main thread. Grants and returns the path. Cancel returns `None`. |
| `pick_save_path(suggested: Option<String>) -> Option<String>` | Opens a native save dialog with `blocking_save_file`, starting from the suggested file name. Grants and returns the path. |
| `confirm_discard() -> bool` | Shows a native Yes/No message dialog (`blocking_show`) asking "Discard unsaved changes?". |
| `read_text_file(path) -> String` | Rejects ungranted paths with `"path not permitted: …"`. Otherwise it calls `fs::read`, then `String::from_utf8`. Errors are mapped as follows: NotFound → `"file not found: …"`, invalid UTF-8 → `"not valid UTF-8: …"`, anything else → `"read failed: …: {err}"`. |
| `write_text_file(path, contents)` | Rejects ungranted paths. Otherwise it calls `fs::write` and maps errors to `"write failed: …: {err}"`. |

**IO helpers.** The IO logic lives in plain functions with no Tauri types, which keeps it unit-testable: `read_text(&Path)`, `write_text(&Path, &str)` and `is_granted(&HashSet<PathBuf>, &Path)`. The commands are thin wrappers around them.

**Unit tests (`cargo test`).**

- A write → read round trip.
- A missing file returns an error containing "file not found".
- Multibyte UTF-8 content (for example `"日本語 ✓ 🎉\n"`) survives a round trip byte-for-byte.
- Invalid UTF-8 bytes return an error containing "not valid UTF-8".
- `is_granted` rejects a path that is not in the set.

**Dialog choice.** Dialogs run on the Rust side through the plugin's Rust API, so the webview needs no `dialog:*` permission, and the `@tauri-apps/plugin-dialog` npm package is not needed. This is what lets the Rust side enforce the user-chosen-path scope (see section 11).

## 6. Tauri configuration

**`tauri.conf.json`.**

- `productName` is `emaki-tauri-editor` and `identifier` is `me.tacogips.emaki-tauri-editor`.
- `build.devUrl` is `http://localhost:1420`, `frontendDist` is `../dist`, `beforeDevCommand` is `npm run dev` and `beforeBuildCommand` is `npm run build`.
- There is one window, labelled `main`: 1000×700, resizable, title `Untitled — emaki`.

**CSP.** Applied to production builds:

```
default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:;
connect-src ipc: http://ipc.localhost; object-src 'none'; base-uri 'none'; frame-ancestors 'none'
```

**Dev CSP.** `devCsp` is identical except that `connect-src` also allows `ws://localhost:1420` for Vite HMR.

**Rules that keep the strict CSP working.**

- There is no `'unsafe-inline'` or `'unsafe-eval'`.
- CSS ships as a linked `style.css` (`<link rel="stylesheet">`), never as an inline `<style>` and never as a CSS import from TypeScript.
- Lazy language chunks are same-origin scripts, which `script-src 'self'` allows.
- Vite uses `base: './'`, so chunk URLs resolve under Tauri's custom protocol.

**`capabilities/default.json`.** Applies to window `main` with exactly these permissions:

- `core:event:allow-listen` and `core:event:allow-unlisten`, which `onCloseRequested` needs
- `core:window:allow-set-title`
- `core:window:allow-destroy`, because `onCloseRequested` destroys the window after the handler unless it is prevented

There is no `core:default`, no fs plugin and no `dialog:*`. If a native run shows that another specific permission is required, add only that permission and record it with the evidence. App commands are allowed by Tauri 2's default, and the path scope in section 5 guards them.

## 7. Frontend behavior (`src/main.ts`)

**Layout.**

- `#editor` uses flex: 1 and fills the window.
- The status bar shows:
  - `#status-msg`, for errors and "Saved"
  - `#lang`, a `<select>` with one option per entry in `languages`, in registry order, with the option value set to `info.id` and the text set to `info.name`
  - `#pos`, showing `Ln {line}, Col {col}`, where both are 1-based and col counts UTF-16 units from the line start

**Document model.** `{ docId: number, rev: number, path: string | null, dirty: boolean, langId: string }` plus the current `EditorHandle`.

- `docId` increments whenever New, Open or Launch replaces the document. Remounts that keep the same document (a language override, or a Save As language change) keep `docId`.
- `rev` is an application-level counter, not the editor's. It increments on every `docChanged` update and survives remounts. A remount creates the editor with `doc: text` and emits no `docChanged`, so it does not change `rev`.

**`mount(text, langId)`.** Destroys the current editor and creates a new one with `doc: text`, `language: await loadLanguage(langId)` and `theme: { tokens: defaultTokenColors }`.

- **Stale loads.** A monotonically increasing token discards stale loads: a slow `loadLanguage` for an earlier open must not replace a newer mount.
- **Load failure.** If `loadLanguage` fails, mount `plaintext` and show the error.
- **After mounting.** Subscribe `onUpdate` so that `docChanged` sets `dirty = true` and refreshes the title, and `selectionSet` or `docChanged` refreshes `#pos`. Then focus the editor.
  - **Superseded by `design-vim.md` §7.** `dirty` is now `!doc.eq(clean)`, measured against the clean baseline as last loaded or saved, and the native `setTitle` calls are serialized. This fixes the native dirty-on-launch bug. The same section adds the vim toggle, the ex mapping and `confirm_open_path`.

**Language detection.**

- With a path: `resolveLanguage({ filename: basename(path) })?.id ?? 'plaintext'`.
- Untitled documents use `plaintext`.
- A Save As to a new name re-detects the language and remounts with the current text if the language changed.
- **Override.** Changing `#lang` remounts with the current text, the same main selection (clamped) and the same `dirty` flag. The override lasts until the next Open or New.

**Title.** `${name}${dirty ? ' •' : ''} — emaki`, where `name` is the path's basename or `Untitled`. It is set with `getCurrentWindow().setTitle(...)` and mirrored to `document.title`; the smoke test asserts on the mirror.

**Actions.**

- **New.** If dirty, run the guard. Then set `path = null` and mount `''` as `plaintext`.
- **Open.** If dirty, run the guard. Then `pick_open_path` → `read_text_file` → mount the text with the detected language and set `dirty = false`. Cancel is a no-op. A read error goes to `#status-msg` and the current document stays unchanged.
- **Save.** If there is no path, run Save As. Otherwise take a snapshot `{ docId, rev, path, text: state.doc.toString() }` before the write, then call `write_text_file(snapshot.path, snapshot.text)`. Completion is conditional:
  - **Success, document unchanged** (`docId === snapshot.docId && rev === snapshot.rev`): set `dirty = false` and show "Saved".
  - **Success, document changed** (the user edited during the write, so `rev` moved): keep `dirty = true`, keep the current editor text untouched, and show "Saved (newer edits unsaved)". The title keeps `•`, and New, Open and close still require confirmation.
  - **Success, document replaced** (`docId` differs; normally impossible because actions are blocked while busy): change nothing.
  - **Error:** document state, text and `dirty` are unchanged, and the error is shown.
- **Save As.** `pick_save_path(basename or 'untitled.txt')`. On cancel (`None`), nothing changes. Otherwise take the snapshot and write it as in Save, with one addition: on success, if `docId` still matches, set `path` to the new path even when `rev` moved, because the file now exists there. Then re-detect the language. If the language changed, remount with the **current** editor text (not the snapshot text), the clamped main selection and the current `dirty` flag. `dirty` is cleared only under the same `docId` + `rev` match rule as Save. On a write error, `path`, the language and `dirty` stay unchanged.
- **Guard.** `dirty ? await invoke('confirm_discard') : true`.
- **Close.** `getCurrentWindow().onCloseRequested(e => { if (dirty && !(await guard)) e.preventDefault() })`.
- **Launch.** `initial_path()`. If it returns a path, open it with `read_text_file`. On error, show the message and start an untitled document. With no path, start an untitled document.

**Shortcuts.** A `keydown` listener on `window` in the **capture** phase, so it runs before emaki's input bridge. `Mod` is `metaKey` on macOS and `ctrlKey` elsewhere.

| keys | action |
|---|---|
| `Mod+N` | New |
| `Mod+O` | Open |
| `Mod+S` | Save |
| `Mod+Shift+S` | Save As |

Matched shortcuts call `preventDefault()` and `stopPropagation()`. Other keys pass through untouched. On macOS, `Ctrl+N` stays the editor's cursor-down.

**Concurrency.** A single `busy` flag drops shortcut actions while a dialog or IO action is in flight. Typing is not blocked during a write. The snapshot `docId`/`rev` check above is what keeps edits made during a pending write marked dirty. The close guard reads the live `dirty` flag, which stays `true` until a matching save completes, so closing while a write is pending still asks for confirmation.

## 8. Mocked IPC for the browser smoke

**Loading the mock.** `main.ts` first runs `if (import.meta.env.MODE === 'mock') await (await import('./mock-ipc')).install()` and only then invokes anything. In a production build `MODE` is `production`, so the branch and the mock module are removed. Verify this by grepping `dist/` for `mockIPC` (expect no match).

**What `install()` does.**

- Calls `mockWindows('main')` and `mockIPC(handler)` from `@tauri-apps/api/mocks`.
- Exposes `window.__tauriEditorMock = { files: Map<string,string>, nextOpen, nextSave, discard: boolean, calls: string[], deferWrite: boolean, failWrite: boolean, releaseWrite(): void, text(): string }`.
  - With `deferWrite` set, `write_text_file` records the contents it was given but returns a pending promise. `releaseWrite()` stores those contents in `files` and resolves the promise.
  - With `failWrite` set, `write_text_file` rejects with `"write failed: …"`.
  - `text()` returns the live editor document. `main.ts` registers it only in mock mode.

**Handler.**

- It implements every custom command in section 5 against `files`, including the "file not found" error.
- It returns `null` for `plugin:window|*` and `plugin:event|*`. If the installed `@tauri-apps/api` version supports `mockIPC(handler, { shouldMockEvents: true })`, use that for events instead.

**`scripts/smoke.mjs`.** This is a Node script and not part of the root vitest suite. It owns the server lifecycle in-process and never spawns a detached process.

1. `createServer({ configFile: <subproject vite.config.ts>, mode: 'mock', server: { port: 0, strictPort: false } })` → `listen()`.
2. Launch Chromium headless with `playwright` and open the URL. Fail on any `pageerror` or console error.
3. Seed `files['/mock/hello.ts'] = 'const a = 1;\n'` and `nextOpen = '/mock/hello.ts'`. Press `Mod+O`. Assert that `#lang` value is `typescript` and the title is `hello.ts — emaki`.
4. Click the editor, type `// edit` at the end, and assert that the title ends with `hello.ts • — emaki`.
5. Press `Mod+S`. Assert that `files['/mock/hello.ts']` contains `// edit`, that the title no longer has `•`, and that `calls` includes `write_text_file`.
6. **Deferred-write regression.**
   1. Set `deferWrite = true`, type ` A` and press `Mod+S`.
   2. While the write is pending, type ` B`. Then call `releaseWrite()` and wait for the status message.
   3. Assert that `files['/mock/hello.ts']` ends with ` A` and does not contain ` B` (the saved snapshot), that `text()` ends with ` A B` (the newer text is kept), and that the title still contains `•`.
   4. Set `discard = false` and press `Mod+N`. Assert that `calls` gained `confirm_discard`, and that the title and `text()` are unchanged.
   5. Set `deferWrite = false` and press `Mod+S`. Assert that `files['/mock/hello.ts']` ends with ` A B` and the title has no `•`.
7. **Write error and cancel.**
   1. Set `failWrite = true`, type ` C` and press `Mod+S`. Assert that the title keeps `•`, `#status-msg` shows `write failed`, and `text()` ends with ` C`. Set `failWrite = false`.
   2. Set `nextSave = null` and press `Mod+Shift+S`. Assert that the path, title and `text()` are unchanged and `calls` has no new `write_text_file`.
   3. Press `Mod+S` to save cleanly.
8. Set `nextOpen = '/mock/notes.unknownext'` with content `x`, set `discard = true`, and open it. Assert that `#lang` is `plaintext`, which checks the fallback.
9. Assert that the `#lang` option count equals `languages.length`, which the script gets from `server.ssrLoadModule` on the repository's `src/language/registry.ts`. This independent count does not come from the page.
10. In `finally`, close the browser and then `server.close()`. Exit 0 only if every check passed. Print a JSON summary.

**Dependency.** `playwright` is pinned to the root version (1.62.1) as a subproject devDependency.

## 11. Decisions

1. **Dialogs run in Rust, and IO is limited to granted paths.** This keeps file IO to `read_text_file`/`write_text_file`, uses `tauri-plugin-dialog`, grants no fs plugin or `dialog:*` permission to the webview, and stops the webview from reading arbitrary paths. It diverges from the intake's guess of JS-side `plugin:dialog|open/save` mocking: the smoke test mocks the custom commands instead.
2. **Consume emaki through Vite aliases and TS paths.** This avoids a `file:` dependency, needs no built `dist`, gives a single CodeMirror instance and leaves the root lockfile untouched.
3. **Remount the editor on Open and on a language override.** emaki fixes the language at creation (an existing non-goal), so this needs no library change.
4. **Use a custom `initial_path` command for the CLI argument.** This avoids adding `tauri-plugin-cli`.
5. **Run the smoke test as a Node script using the `playwright` library with an in-process Vite server.** This matches the root `scripts/e2e.mjs` style, gives an owned lifecycle and adds no `@playwright/test`.
6. **Generate icons from an original placeholder image with `npx tauri icon`.** Commit only the files `tauri.conf.json` references; no chilla branding.

## 13. Risks

- Network-dependent `npm install`/cargo fetch and a long first Tauri compile (V3 and V5 need generous foreground timeouts).
- The exact `core:*` permissions needed for `onCloseRequested` vary by Tauri minor version. Section 6 lists the expected set; a native run may require one more specific permission.
- `blocking_*` dialog calls must stay inside `async` commands. Calling them from a sync command, which runs on the main thread, deadlocks.
- WebGL2 in headless Chromium for the smoke test relies on the software GL that the root e2e already uses.
